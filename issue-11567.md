# Plan: generate the past IETF meetings / proceedings index (#11567)

Issue: https://github.com/ietf-tools/datatracker/issues/11567

## Scope

#11567 combines three older issues:

- **#2490:** generate the past-meetings/proceedings index from datatracker data, so the Wagtail page no longer needs manual updates. The statistics should come from a single source.
- **#10919:** a page showing only IETF plenary meetings that closely copies https://www.ietf.org/meeting/past/. For each meeting it shows an "IETF NNN" heading, dates, location, host(s), a Proceedings link and a Survey Results link.
- **#2617 (size XS):** on `/meeting/past`, link IETF meetings to their proceedings instead of their agenda.

The issue discussion settled on these points:

- Survey links should not use `ProceedingsMaterial`. They arrive irregularly after the proceedings are finalized, and editing proceedings materials after that is meant as an escape hatch.
- Use a "Meeting External URL" class that follows the Doc/Group/Person external-resource pattern.
- There are about 50 past survey URLs. Future ones could follow a regular naming pattern.

The live www page also shows **"N onsite participants, M online participants"** and **"City, Country & Online"**. The issue text doesn't list these, but #2490 asks for the statistics.

## What already exists

| Need | Existing support |
|---|---|
| Meeting number, dates, city, country | `Meeting.number/date/days/city/country` and `end_date()` ([ietf/meeting/models.py](ietf/meeting/models.py#L70)) |
| Hosts | `MeetingHost` (name plus logo) ([ietf/meeting/models.py](ietf/meeting/models.py#L1543)), edited by the Secretariat through `views_proceedings.edit_meetinghosts`. The logo is **required** (`blank=False`). |
| Proceedings link | `views.proceedings` already redirects meetings before 97 to `PROCEEDINGS_V1_BASE_URL` ([ietf/meeting/views.py](ietf/meeting/views.py#L4859)) |
| Attendance | `Meeting.get_attendance()` returns onsite/remote counts, but it is expensive and returns `None` before IETF 110. `Meeting.attendees` holds a single number: backfilled for old meetings, otherwise set from onsite check-ins by the registration sync ([ietf/meeting/utils.py](ietf/meeting/utils.py#L2115)). |
| External-URL pattern | Abstract `ExtResource` ([ietf/doc/models.py](ietf/doc/models.py#L1406)) is used by `DocExtResource` and `SubmissionExtResource`, along with `BaseExtResourceForm` and the textarea-parsing `ExtResourceForm` ([ietf/doc/forms.py](ietf/doc/forms.py#L204)). `GroupExtResource` and `PersonExtResource` duplicate the fields instead of using the base class. |

**One catch with that pattern:** every existing extresource editor (doc, submission, group and person) accepts any `ExtResourceName`. If we add a `survey_results` slug to `ExtResourceName`, people could pick it on documents, groups and person profiles.

## Proposed changes

### 1. Model: per-meeting external URLs

- In `ietf/meeting/models.py`, add `MeetingExtResource(ExtResource)` with `meeting = ForeignKey(Meeting)`. It inherits `clean()`, `to_form_entry_str()` and URL validation.
- Choose how to name the URL types:
  - **Option (a), recommended:** a new `MeetingExtResourceName(NameModel)` in `ietf/name/models.py` with its own slugs (`survey_results`, with room for more later). This keeps the shared `ExtResourceName` vocabulary clean. Because `validate_external_resource_value` reads `name.type` and `name.slug`, the new model needs a `type` FK to `ExtResourceTypeName` too.
  - **Option (b):** add a `survey_results` slug to `ExtResourceName` and restrict which slugs each editor accepts. That requires changes to the doc, group, person and submission editors ([ietf/group/forms.py](ietf/group/forms.py#L167), [ietf/ietfauth/views.py](ietf/ietfauth/views.py#L352)) so they exclude it.
- Migrations:
  - `meeting/0021_meetingextresource`
  - `name/0021_…`: the schema change plus a data migration that seeds `survey_results`
  - Regenerate `ietf/name/fixtures/names.json`.
- Supporting changes:
  - Register the new models in admin: `ietf/meeting/admin.py`, plus `ietf/name/admin.py` for option (a).
  - Add tastypie resources in `ietf/meeting/resources.py`, plus `ietf/name/resources.py` for option (a). Without them, `test_all_model_resources_exist` ([ietf/api/tests.py](ietf/api/tests.py#L1924)) fails.
  - Add a factory in `ietf/meeting/factories.py`.
- Host URLs: the issue says "(and host)" URLs, but the www page shows host names without links, and `MeetingHost` already covers names. A host homepage URL could become a second slug later if anyone wants it.

### 2. Secretariat editing UI

- Add a new view, `views_proceedings.edit_extresources(request, num)`, decorated with `@role_required('Secretariat')`:
  - It uses `ExtResourceForm(extresource_form_class=MeetingExtResourceForm)`, where `MeetingExtResourceForm(BaseExtResourceForm)` sets `Meta.model = MeetingExtResource`.
  - Saving replaces all of the meeting's resources, like `update_doc_extresources` ([ietf/doc/utils.py](ietf/doc/utils.py#L1367)).
  - It is **not** blocked by `proceedings_final`, because survey results arrive after the proceedings are finalized.
- URL: `^proceedings/extresources/edit/$` in the IETF-only patterns, next to `proceedings/meetinghosts/edit/`.
- Template: `meeting/proceedings/edit_extresources.html`, linked from the meeting materials page next to "Edit meeting hosts".
- Backfilling the ~50 survey URLs and the hosts of older meetings:
  - Write a one-off management command that reads a CSV of `number,slug,url` supplied by the Secretariat.
  - Backfilling hosts runs into the required logo. Either make `MeetingHost.logo` optional (a migration, plus template guards wherever logos are shown on proceedings pages), or accept that older meetings show no host.

### 3. The index page

- URL: `/meeting/proceedings/` is not available. The optional-number URL patterns already map it to the current meeting's proceedings ([ietf/meeting/urls.py](ietf/meeting/urls.py#L149)). Add `^past/ietf/?$` next to `^past/?$` ([ietf/meeting/urls.py](ietf/meeting/urls.py#L131)) instead.
- View: `views.past_ietf_meetings`.
  - Query `Meeting.objects.filter(type_id='ietf', date__lte=today)`, ordered by meeting number descending. The number has to be cast because `number` is a CharField.
  - Add `prefetch_related('meetinghosts', 'meetingextresource_set__name')`.
  - Keep the number of queries the same no matter how many meetings there are, in line with the recent perf work, and cover this with an `assertNumQueries` test.
- Template: `meeting/past_ietf.html`. For each meeting:
  - An `<h2>IETF NNN</h2>` heading.
  - The date range in www style, for example "July 18-24, 2026", or "Oct 30 - Nov 5" when the meeting spans two months. Add a small template filter or model helper for this.
  - The location as `city, get_country_display`, plus "& Online" for hybrid meetings. The fully online meetings 108–111 need a special case.
  - "Hosted by A & B".
  - A Proceedings link built with `{% url 'ietf.meeting.views.proceedings' num=… %}`, which already handles the v1 redirect. Meetings 28 and earlier link directly to the PDF, as `past.html` does today.
  - A Survey Results link when one exists.
- Attendance counts: calling `get_attendance()` for every meeting is too slow, and it returns `None` before 110. Two options:
  - **(a)** Show only `Meeting.attendees`: a single number with no onsite/online split.
  - **(b), recommended if we want the split:** add `Meeting.remote_attendees`. Set it in the same registration-sync step that sets `attendees`, and backfill it from the figures currently on the www page.
- Caching: wrap the page in `{% cache %}` as `past.html` does. Either invalidate the cache when a `MeetingExtResource` or `MeetingHost` is saved, or accept up to an hour's delay.
- Menu: point the past IETF meetings link in [ietf/templates/base/menu.html](ietf/templates/base/menu.html#L375) at the new page instead of www.ietf.org.
- www.ietf.org integration: either Wagtail links or redirects to the datatracker page, or we also provide a `past/ietf.json` endpoint for www to render. The HTML page alone is enough to end the manual updates.

### 4. #2617 (fold in)

- In [ietf/templates/meeting/past.html](ietf/templates/meeting/past.html), for meetings after 28, link to the proceedings URL instead of `{% url 'agenda' %}`.
- Update any test that checks for the agenda link.

### 5. Tests

- Model and form:
  - valid and invalid slugs
  - a value that is not a URL
  - a round trip through `to_form_entry_str`
- Edit view:
  - restricted to the Secretariat (other users get a login redirect or 403)
  - saving replaces the existing resources
  - works on a meeting whose proceedings are finalized
- Index view:
  - lists only IETF meetings, in the right order
  - joins multiple hosts correctly
  - shows the survey link when one exists and omits it otherwise
  - links a v1 meeting to its proceedings correctly
  - formats a date range that spans two months
  - keeps the query count fixed
- Elsewhere:
  - the API resource test
  - the `names.json` consistency check
  - the #2617 link change

## Decisions needed before building

1. **Name vocabulary:** a new `MeetingExtResourceName` (recommended), or reuse `ExtResourceName` and filter the new slug out of the other editors?
2. **Attendance figures:** show onsite and online counts (needs a new field and a backfill), a single total, or none?
3. **Hosts for older meetings:** make `MeetingHost.logo` optional so they can be backfilled?
4. **Page URL and www integration:** `/meeting/past/ietf/` with a link or redirect from www, or also a JSON endpoint?
